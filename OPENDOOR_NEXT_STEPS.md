# OPENDOOR // THE ONE FILE THAT ACTUALLY MATTERS

Think of this as the kitchen whiteboard. Everything else goes foggy. Keep me updated, keep me short.

**The whole game:** 1,200+ repos scored. One job left: **get contributors merged, get them to tell someone, and charge them for the parts that turn their hours into merges instead of fog.**

## 1) WHERE WE SIT (right now, honest)

Repos scored (S→D, C-Rank), ranked by lang, filters, watchlists, AI vibe-check, OG images, hall-of-fame, good-first-issue, badge SVG, score history. Live product.

- Contributors *browse* — they find "which door", but that's it. **There is no plan for actually getting to the merge.** That's the gap. That's the phase.
- No pay yet. Site is free.
- Growth: SEO pages + badges. Good. But nobody comes back weekly unless they need to.

## 2) THE MISSION

**Right-weight the gamble.** Contributor's only question: does this repo answer me, will I merge, will I not be ghosted? Answer it *before* they start. Then *carry them past the line* — and let them flex it.

Every loop → every merge → every share → every badge → every subscriber.

## 3) WHO WE'RE FOR

- **Newbie** (0 merged): scared, "am I good enough" — needs a calm first merge.
- **Mid** (1–10 merged): knows how, resents wasted nights on ghost repos.
- **Veteran** (10+ merged, job-hunting): wants portfolio proof of wins, not resume claims.
- **Maintainer:** wants more good hands, not spam; needs their grade + "how do I get better".
- **Company:** wants open-source presence and engineers who land PRs in top repos. Money floor. Build after traction (§8).

## 4) WHAT THEY COMPLAIN ABOUT (real, borrowed from Reddit/DEV)

- "PR sat for weeks, no reply" — the #1 ghost.
- "Good-first-issue but never got assigned."
- "I fixed exactly what they asked, still ghosted."
- "Bus-factor-1 projects scare me."
- "Nobody tells me if a repo is hostile; you only learn by trying."
- "Look at my GitHub — landed PRs in S-tier repos, that's credibility."

The product: **kill the wasted-hours before it starts, make every attempt worth it, and let merged-and-happy contributors tell the world.**

## 5) WHAT CONTRIBUTORS GET (the depth / the free unlock)

### 5.1 — "Door of the day" (free viral, 1 repo per day)
- Every day pick **1 full repo unlocked** — the entire insight free (all C-Rank axes, deep dive).
- To see tomorrow's? **Share today's** (WhatsApp / Telegram / X / Discord). Share-unlock.
- Cute copy: "Today's door is open. See it. Want tomorrow's? Share this one."

### 5.2 — Metrics on the contributor's side
- **Competing PR count** on the issue — avoid contested issues (data: 3+ competing PRs = ~8% merge rate; zero competition = ~52%).
- **Estimated difficulty** (LOC / typical time) — so "keep it under 50 lines" (<50 LOC ≈ 48% merge, >200 ≈ 18%).
- **Toxic tracer** — sentiment/flag comments in its PR threads.
- **Door trajectory** — getting more welcoming? Trend arrows on every repo card.
- First-timer success rate, response hours, merges/week chips (exists, sharpen).

### 5.3 — Personal dashboard (logged in)
- Door history (watches, tracked PRs, merges, ghost flags).
- "My merge-rate by repo" — the doors I walked.
- Streaks, share-pull donuts, contributor grade + own badge (mirror of C-Rank with GUI).

### 5.4 — "Second door" hook
- Reminder: "Your first door opened. Close the second?" (fact: 1st PR ≈ 12% merge, 2nd ≈ 28%, 3rd ≈ 45%, 4th+ ≈ 67%).
- Show the curve in the UI once. Familiarity is merge math.

## 6) CUTE GUTSY NUDGES (retention)

- **Doorbell push:** Opendoor tells the second a maintainer replies on a tracked PR. No refreshing GitHub.
- **Ghost-walker:** tracked PR silent >48h → kind nudge: "doors stick, but it's rarely you — here's a polite bump." One-click copy.
- **"You earned it" pack:** confetti + shareable "My first merge via Opendoor" card.
- **Weekend letter:** "This week 3 doors went from B → A. Play."

## 7) MONETIZATION (arcs — buildable, India/UPI-true)

Price anchors from real dev tools: WakaTime $9/$14 single, $19–24/dev team. Keep it simple.

> **Core rule: never lock the data. Lock the time-savers and the career tools.** C-Rank + raw metrics stay public forever. Gate the walking, not the map.

### Arc A — Pro ($5/mo, ~₹399)
- Unlimited door-of-the-day + issue-competition map.
- PR likelihood per candidate repo.
- Weekly personal "5 doors that want your PRs" email.
- Unlimited shares (free = 3/wk).
- First-merge track: 5 curated repos + issue blueprint from CONTRIBUTING.

### Arc B — Recruiter Pro ($9–12/mo)
- Auto winner-card per merged PR: LOC, language match, merge speed, notes.
- Recruiter-mode public profile + one-click copy.
- GitHub profile audit (fix the 3% that kills recruiter scans).
- Quantify everything into "S-tier contributor" bullet points.

### Arc C — Sponsored doors
- "Looking for contributors" strip on home + repo pages — $100–300/mo.
- Label as sponsored, never mixed into rankings. Trust IS the product.

## 8) WHY MAINTAINERS & COMPANIES PAY

**Maintainer (~$20/mo per project):**
- See the repo exactly as a contributor does (monthly report).
- Benchmark vs 20 peers in language + size bucket.
- "3 ways to level up" from gap analysis (no CONTRIBUTING, slow response, bus factor 1).
- Spam-noise counter (already have `isBot`).
- Claim + badge the repo: "welcoming to contributions" badge in README.

**Company (build after traction):**
- OSPOs answer "are we welcoming to PRs?" — give them the benchmark evidence.
- Org health report per quarter ($2–4k/yr).
- Opt-in talent leads: devs who land PRs in S-tier repos, matched to roles.

## 9) THE GUTSY PLAY — ball on door

- **Proactively open PRs to friendly high-C-Rank repos** adding an "OpenDoor: contribution welcome" badge/link (CM-count tracked).
- Amend, small, README-only. Doesn't touch the repo's code.
- Every badge = backlink + a first-PR success for a new contributor + product distribution.
- Only pick repos whose maintainers would love it — where doors are actual doors.

## 10) THE FLOW

```
find door → C-Rank read (free) → pick issue (contest radar) 
→ hatch PR (blueprint) → door says "contributor!" (doorbell, confetti)
→ merge → share card → recruiting target
→ maintainer sees C-Rank + pay for insights
```

## 11) RULES / NOT ALWAYS OKAY

- Never gate C-Rank data. It's the trust.
- Never hardcode mock data — every number is real from GitHub.
- Never ship a paywall on a secret; always tie money to time saved, not data hidden.
- Keep share-to-unlock optional. Hobby file for free.
